# P1 Acceptance Record

Task IDs / design sections: P1-01 to P1-05 / the whole
[P1: Text Viewing and Log Troubleshooting](../../design/p1-preview-logs.md) design.

## Scope and intentional compatibility changes

- `GET /file-viewer` keeps its old behaviour when `sfe4j.logs.enabled` is `false`: a bounded head
  preview rendered as escaped plain text. With the flag enabled it also accepts `mode`, `lines` and
  `charset` and renders the follow controls.
- The new JSON API lives under `/sfe4j/api` and is registered only when `sfe4j.logs.enabled=true`;
  with the flag disabled both endpoints answer 404 and no scheduler thread is created.
- The `file` parameter of the API is the same parameter the page uses and goes through the same
  access facade; there is no separate read path.
- `TextFileReader` now delegates to `TextReadService`. A missing target is reported as
  `FILE_NOT_FOUND` instead of `FILE_IO_ERROR`, a non regular target as `UNSUPPORTED_PREVIEW`, and a
  UTF-16 file with a byte order mark is decoded as UTF-16 instead of being rejected as binary.
- Binary detection changed from "contains a NUL byte" to a heuristic over the decoded content
  (printable ratio and decoding error ratio). A mostly binary file with a few undecodable bytes is
  still shown with replacement characters; NUL characters are not counted, so UTF-16 text read with
  the wrong encoding is not rejected and can be corrected from the page.
- The page keeps its old look when the feature is off; the new script is a separate file
  (`static/js/sfe4j-text-viewer.js`) and the vendored Bootstrap, jQuery and DataTables files are
  untouched.

## Executed end to end checks with the packaged sample

- `GET /sfe4j/api/text?mode=tail&lines=2` returns `line-4\nline-5\n`, a cursor and
  `nextPosition=35`; `mode=head&lines=1` returns `line-1\n` with `truncated=true`.
- An unsupported encoding answers 400, a path outside the base directory answers 403.
- `GET /sfe4j/api/follow` sends `event:snapshot`, then one `event:append` per appended line with
  increasing `id` values; a copytruncate (`> file`) sends `event:reset` with `reason:truncated`
  followed by a new snapshot; heartbeats are sent as SSE comments while the file is idle.
- With `--sfe4j.logs.enabled=false` both API endpoints answer 404 and the page renders without the
  follow controls.
- The hostile file `<script>alert(1)</script>` is rendered as `&lt;script&gt;` in the page.

## Follow-up in 1.2.1: line numbers and wrapped text

The first implementation put the numbers and the text in two sibling columns of one scroll
container. The numbers counted logical lines while the text occupied more visual rows as soon as a
line wrapped, so every number below the first wrapped line pointed at the wrong text.

Each logical line is now a single row that holds its own number and its own text, the number cell
is sticky at the left edge for horizontal scrolling, and the frame still has exactly one scroll
bar. `TemplateRenderingTest.theViewerKeepsNumbersAndTextInsideOneScrollingContainer` fails if a
second number column is ever reintroduced. The rows are ordinary elements with text nodes only, so
file content is still never parsed as markup.

## Performance scenario, sample size, metrics and measurement

Not executed. The acceptance items that need a real workload were not measured:

- tail duration on a file larger than 1 GiB (only the bounded scan is covered by a test with a
  40 000 line file and a 4 KiB scan budget);
- 20 connections for 30 minutes with heap, thread, handle and queue peak recording;
- 100 connect/disconnect cycles and the shutdown of the application leaving no read task behind.

## Not executed, failure reasons and remaining risks

- The queue bound is an estimate. The servlet container does not report how much of a server sent
  event response is still buffered, so `LogFollowManager` treats the bytes handed over since the
  last idle round as queued and closes the connection with a `gap` event past
  `sfe4j.logs.max-queue-bytes`. A slow client is therefore detected late or, for a burst that ends
  in an idle round, not at all.
- A session id rotation ends the connection with a `reset` instead of migrating it; the browser
  reconnects and receives a new snapshot.
- Overwriting a file with the same length, or truncating it and refilling it inside one poll
  interval, cannot be detected from the length and the file key alone.
- The first release does not expose a client supplied physical file offset; resume works through
  the short lived signed cursor only.
- Syntax highlighting is not implemented (P1-06); JSON, XML and YAML are displayed as plain text.
- Windows CI and real restricted identity permission tests are still missing, as in P0.
- `SecureDirectoryStream` is still not used, so the P0 TOCTOU window between the path check and
  opening the file remains.
