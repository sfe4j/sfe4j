## Scope and intentional compatibility changes

- The three old routes and their parameter names are kept: `GET /file-explorer`,
  `POST /file-explorer`, `GET /file-viewer`, `GET /file-downloader`; `POST /file-explorer/logout`
  is new and drops SFE4J grants only.
- `FileExplorerService.readFile(String)` keeps its signature, runs with an anonymous context and
  must refuse a protected target.
- The preview no longer renders HTML, it is an auto escaped `<pre>`.
- Out of range requests no longer fall back to the base directory, they are answered with 403.
- The base directory and every protected directory must exist, otherwise startup fails.
- The container image publishes `/data` instead of the file system root; the property defaults of
  `sfe4j.base-dir-path` and `sfe4j.restrict-to-base-dir` are unchanged (`/`, `false`).
- An out of range numeric value fails startup instead of degrading silently.

## Environment

- Local repository on macOS (Apple silicon), JDK 25 (Temurin), Maven Wrapper 3.9.x, offline build.
- Every file based test uses an `@TempDir` temporary directory and never real host paths.

## Performance scenario, sample size, metrics and measurement

Not executed. The 1 GiB download heap benchmark, file descriptor and handle release after an
interrupt, and the handle growth over 100 interrupted downloads were not measured. Only the unit
test level coverage exists: bounded reads (at most `preview.max-bytes`) and concurrency 429.

## Not executed, failure reasons and remaining risks

- Integration tests: real HTTP download interruption, handle release, large file heap benchmark.
  Failsafe configuration and an integration test skeleton with a random port are missing.
- Windows CI path and symbolic link tests: all current tests run in POSIX temporary directories,
  drive letters and backslash file names are not covered.
- Permission tests were not run under a real restricted identity.
- `SecureDirectoryStream` is not used, so a TOCTOU window remains between the path check and
  opening the file; deployments still need read-only mounts or isolation.
- Download concurrency uses a bounded semaphore instead of a dedicated thread pool, waiting still
  happens in the container Servlet thread pool; transfer timeouts and a waiting queue are not
  configurable yet.
- Eviction of the bounded rate limit cache relies on periodic cleanup and is single instance by
  default; shared rate limiting across instances is left to P2.
