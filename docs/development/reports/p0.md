## 实现范围及有意兼容性变化

- 保留三个旧路由与参数名：`GET /file-explorer`、`POST /file-explorer`、`GET /file-viewer`、`GET /file-downloader`；新增 `POST /file-explorer/logout`（仅清除 SFE4J 授权）。
- `FileExplorerService.readFile(String)` 保留签名，按匿名上下文执行，受保护目标必须拒绝。
- 预览不再渲染 HTML，改为自动转义的 `<pre>`。
- 越界请求不再回退到基础目录，统一返回 403。
- 基础目录与保护目录必须存在，否则启动失败。
- 容器镜像默认发布 `/data` 而不是文件系统根；`sfe4j.base-dir-path` 与 `sfe4j.restrict-to-base-dir` 的属性默认值保持不变（`/`、`false`）。
- 数值配置超出范围时启动失败，不静默降级。

## 运行环境

- macOS（Apple 芯片）本地仓库，JDK 25（Temurin），Maven Wrapper 3.9.x，离线构建。
- 所有文件测试使用 `@TempDir` 临时目录，不依赖宿主机实际路径。

## 未执行项、失败原因和剩余风险

- 集成测试：真实 HTTP 下载中断、句柄释放、大文件堆基准。缺少 Failsafe 配置与随机端口集成测试骨架。
- Windows CI 的路径与符号链接测试；现有测试全部在 POSIX 临时目录中运行，未覆盖盘符与反斜杠文件名。
- 权限测试未在实际受限身份下执行。
- 未使用 `SecureDirectoryStream`，路径检查与打开之间仍有 TOCTOU 窗口；部署仍需只读挂载或隔离。
- 下载并发使用有界信号量而非独立线程池，等待仍发生在容器 Servlet 线程池中；传输超时与等待队列配置尚未引入。
- 有界限速缓存的淘汰依赖定时清理，默认单实例行为，多实例部署的共享限速留给 P2。
